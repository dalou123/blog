    # 六、RAG（检索增强生成）

    大模型的知识截止到训练日期，不知道你的公司文档、内部规范、最新数据。RAG（Retrieval-Augmented Generation）让模型能访问你的私有知识库，回答基于真实文档的问题。

    # 6.1 RAG 解决什么问题

    直接问模型"我们公司的请假流程是什么"，它不知道。你把所有公司文档塞进 Prompt，超过上下文限制。

    RAG 的思路：

    用户提问
    ↓
在知识库里找到最相关的几段文档（检索）
    ↓
把这几段文档 + 用户问题一起发给模型
    ↓
模型根据文档内容回答（生成）

    关键点：不是把所有文档都给模型，而是每次只给最相关的几段。

    # RAG 的完整流程

    离线阶段（文档入库）：
文档 → 分片（Chunking）→ 向量化（Embedding）→ 存入向量数据库

在线阶段（用户提问）：
用户问题 → 向量化 → 向量数据库检索 → 取出相关文档 → 拼入 Prompt → 模型生成回答

    # 6.2 Embedding：文本变向量

    Embedding 是把文本转换成一串数字（向量），语义相近的文本，它们的向量在高维空间中的距离也近。

    import { OpenAIEmbeddings } from '@langchain/openai'

const embeddings = new OpenAIEmbeddings({
  model: 'text-embedding-3-small',  // 1536 维，性价比好
  apiKey: process.env.OPENAI_API_KEY,
})

// 单个文本向量化
const vector = await embeddings.embedQuery('Vue3 的响应式系统基于 Proxy 实现')
console.log(vector.length)   // 1536
console.log(vector.slice(0, 3))  // [-0.012, 0.034, -0.089, ...]

// 批量向量化（批量折扣，更便宜）
const vectors = await embeddings.embedDocuments([
  'Vue3 的响应式系统基于 Proxy',
  'React 使用虚拟 DOM',
  '今天天气不错',
])

    # 余弦相似度：衡量两段文字有多像

    function cosineSimilarity(vecA, vecB) {
  let dot = 0, normA = 0, normB = 0
  for (let i = 0; i < vecA.length; i++) {
    dot   += vecA[i] * vecB[i]
    normA += vecA[i] * vecA[i]
    normB += vecB[i] * vecB[i] 
  }
  return dot / (Math.sqrt(normA) * Math.sqrt(normB))
  // 返回 -1 到 1，越接近 1 越相似
}

// 实测示例（text-embedding-3-small）：
// "Vue3 props 怎么传?" vs "Vue3 中使用 defineProps 接收父组件数据"  → 0.87（很相似）
// "Vue3 props 怎么传?" vs "React 的 props 怎么用？"               → 0.72（话题相近）
// "Vue3 props 怎么传?" vs "今天股市大涨"                           → 0.21（无关）

    # 6.4 文档分片（Chunking）

    大文档不能整个存入向量库，要先分成小片段，原因：

    • 向量化有长度限制（通常 512~8000 tokens）
    • 太长的文档向量不够精确，小片段的语义更集中
    • 检索时只取最相关的片段，减少无关内容干扰
    import { RecursiveCharacterTextSplitter } from '@langchain/textsplitters'

const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 500,      // 每个片段最多 500 字符
  chunkOverlap: 50,    // 相邻片段重叠 50 字符（防止语义在边界断裂）
  // 分割顺序：先按段落，不够再按句子，再按词，最后按字符
  separators: ['\n\n', '\n', '。', '，', ' ', ''],
})

const longText = `...一篇很长的技术文档...`

// 分成多个 Document 对象
const chunks = await splitter.createDocuments(
  [longText],
  [{ source: 'my-doc', title: '文档标题' }]  // 每个 chunk 都继承这个 metadata
)

console.log(`${longText.length} 字 → ${chunks.length} 个分片`)

    分片大小的经验值：

    • 对话记录：200~400 字符，按对话轮次分
    • 代码文件：按函数或类分割，而不是按字符数
    • Overlap：通常是 chunkSize 的 10%~15%

    # 6.5 构建完整 RAG 链

    import { ChatPromptTemplate } from '@langchain/core/prompts'
import { StringOutputParser } from '@langchain/core/output_parsers'
import { RunnableSequence, RunnablePassthrough } from '@langchain/core/runnables'

// 1. 把向量库封装成检索器
const retriever = vectorStore.asRetriever({
  k: 3,
  searchType: 'similarity',
})

// 2. RAG 提示词
const ragPrompt = ChatPromptTemplate.fromMessages([
  ['system', `你是知识库问答助手。根据参考文档回答用户问题。
规则：
- 只基于参考文档回答，不要使用文档外的知识
- 如果文档中没有相关内容，明确说"文档中没有找到相关信息"
- 在回答末尾标注参考来源`],
  ['human', `参考文档：
{context}

用户问题：{question}`],
])

// 3. 格式化检索文档
function formatDocs(docs) {
  return docs
    .map((doc, i) =>
      `[${i + 1}] 来源：${doc.metadata.title}\n${doc.pageContent}`
        )
    .join('\n\n---\n\n')
}

// 4. 组装 RAG 链（LCEL 方式）
const ragChain = RunnableSequence.from([
  {
    // 并行：检索文档 + 透传问题
    context: retriever.pipe(formatDocs),
    question: new RunnablePassthrough(),
  },
  ragPrompt,
  model,
  new StringOutputParser(),
])

// 5. 使用
const answer = await ragChain.invoke('Vue3 的 computed 和 methods 有什么区别？')
console.log(answer)

    # 6.6.2 多路召回（Multi-Query Retrieval）

    用多个查询分别检索，合并去重，提高召回率：

    async function multiQueryRetrieval(vectorStore, questions) {
  const allDocs = new Map()  // Map 自动去重

  for (const q of questions) {
    const docs = await vectorStore.similaritySearch(q, 3)
    docs.forEach(doc => {
      const key = doc.pageContent.slice(0, 50)
      if (!allDocs.has(key)) allDocs.set(key, doc)
    })
  }

  return [...allDocs.values()]
}

// 用原始问题 + 改写后的查询，多路召回
const allRewrittenQueries = await rewriteChain.invoke({ question })
const allDocs = await multiQueryRetrieval(vectorStore, [question, ...allRewrittenQueries])

    # 6.6.3 重排序（Reranking）

    向量检索召回的文档不一定都有用，用模型对相关性打分，只取高分的：

    async function rerank(question, docs, topK = 3) {
  const rerankPrompt = ChatPromptTemplate.fromMessages([
    ['system', '对文档和问题的相关性打分（0-10），只输出数字。\n10=完全回答了问题，5=部分相关，0=完全无关'],
    ['human', '问题：{question}\n\n文档：{doc}'],
  ])

  const chain = rerankPrompt.pipe(model).pipe(new StringOutputParser())

  const scored = await Promise.all(
    docs.map(async (doc) => {
      const score = parseFloat(
        await chain.invoke({ question, doc: doc.pageContent.slice(0, 300) })
      )
      return { doc, score }
    })
  )

  return scored
    .sort((a, b) => b.score - a.score)
    .slice(0, topK)
    .map(r => r.doc)
}

    # 6.7 完整 RAG 服务接口设计

    // server.js

// POST /api/documents - 上传文档
// body: { title, category, content } 或 multipart file
app.post('/api/documents', upload.single('file'), async (req, res) => {
  const content = req.file ? req.file.buffer.toString('utf-8') : req.body.content
  const docId = `doc_${Date.now()}`

  // 分片
  const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 500, chunkOverlap: 50 })
  const chunks = await splitter.createDocuments(
    [content],
    [{ docId, title: req.body.title, category: req.body.category }]
  )

  // 存入向量库
  const vs = await getVectorStore()
  await vs.addDocuments(chunks)

  res.json({ success: true, docId, chunks: chunks.length })
})

// DELETE /api/documents/:docId - 删除文档
app.delete('/api/documents/:docId', async (req, res) => {
  const vs = await getVectorStore()
  await vs.delete({ filter: { docId: req.params.docId } })
  res.json({ success: true })
})

// POST /api/chat/stream - 流式问答
app.post('/api/chat/stream', async (req, res) => {
  const { question, category } = req.body

  res.setHeader('Content-Type', 'text/event-stream')
  res.setHeader('Cache-Control', 'no-cache')

  const send = (event, data) =>
    res.write(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`)

  const vs = await getVectorStore()

  // 检索，推送来源
  send('status', { message: '正在检索相关文档...' })
  const filter = category ? { category } : undefined
  const docs = await vs.similaritySearchWithScore(question, 4, filter)
  const relevant = docs.filter(([, score]) => score > 0.4)

  send('sources', {
    sources: relevant.map(([doc, score]) => ({
      title: doc.metadata.title,
      score: score.toFixed(3),
      preview: doc.pageContent.slice(0, 80),
    })),
  })

  if (!relevant.length) {
    send('token', { token: '知识库中未找到相关内容' })
    send('done', {})
    return res.end()
  }

  // 生成回答，流式推送
  const context = relevant.map(([d]) => d.pageContent).join('\n\n')
  const stream = await ragChain.stream({ context, question })
  for await (const chunk of stream) {
    send('token', { token: chunk })
  }

  send('done', {})
  res.end()
})

    <script setup>
import { ref } from 'vue'

const sources = ref([])

async function askQuestion(question) {

import { useState, useCallback } from 'react'

export function useRag() {
  const [sources, setSources]     = useState([])
  const [answer, setAnswer]       = useState('')
  const [statusMsg, setStatusMsg] = useState('')
  const [loading, setLoading]     = useState(false)

  const ask = useCallback(async (question) => {

    setSources([])

      buffer = parts.pop() ?? ''

      for (const part of parts) {
        const lines = part.split('\n')

        for (const line of lines) {
          if (line.startsWith('event: ')) event = line.slice(7)

    # 6.9 常见问题和处理方式

    问题1：检索结果相关性差

    可能原因：文档分片太大导致语义不集中；分片太小导致缺少上下文；问题和文档的表述风格差异太大。

    处理：调小 chunkSize（300~500）；用查询改写；测试不同的相似度阈值（一般 0.4~0.6 是好的过滤点）。

    问题2：模型"幻觉"，生成了文档里没有的内容

    系统提示词要明确约束：

    const systemPrompt = `你是文档问答助手。
严格规则：
- 只根据参考文档回答，不使用文档之外的任何知识
- 如果文档中没有找到相关信息，直接说"文档中没有相关内容"
- 不要推测、补充或扩展文档没有提到的内容`

    # 6.10 本章小结

    • RAG 的本质：检索（找到相关文档）+ 生成（模型根据文档回答），解决模型知识截止和私有文档问题
    • Embedding 把文本转成向量，语义相近的文本向量距离近，这是语义搜索的基础
    • 文档要先分片再存储，chunkSize 500 左右、overlap 50 左右是比较通用的起点
    • LCEL 的 RunnableSequence + RunnablePassthrough 可以优雅地组装检索 → 格式化 → 生成的完整链
    • 进阶技巧：查询改写提升召回质量，多路召回增加覆盖面，重排序筛选最相关的，对话历史感知处理多轮问答
    • 服务端通过 SSE 分阶段推送：先推送来源（让用户看到检索到了哪些文档），再流式推送答案
    • 系统提示词必须明确约束模型只根据文档回答，防止幻觉

    下一章：Agent 智能体 — 让模型自主规划步骤、调用工具、反思执行结果，完成更复杂的任务。
